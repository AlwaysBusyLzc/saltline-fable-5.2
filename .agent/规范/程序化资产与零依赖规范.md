# 程序化资产与零依赖规范

## 1. 核心设计原则（Saltline 哲学）
传统 3D 游戏往往依赖数百兆的 `.gltf` 模型与大型 PNG 贴图，存在资源体积庞大、加载缓慢、跨域断链等风险。
本项目沿用 Saltline 的**全代码内聚（Code-Only Procedural Assets）**技术方案：
- **模型零外部依赖**：角色、滑板、古代战舰、码头、岛屿均通过 Three.js 基础几何体与程序化算法拼接合成。
- **纹理贴图程序化合成**：不使用外部位图，全部通过 Canvas 2D 算法渲染或 GLSL 纯数学噪声（FBM、Voronoi、Perlin）动态生成。
- **音效程序化合成**：基于 Web Audio API 振荡器与滤波包络算法实时合成浪涛、引擎推进、水花冲溅声。

## 2. 程序化几何体拼装与合批规范
1. **多形体组合与矩阵变换**：
   - 使用轻量工具函数，在局部坐标系内对 `BoxGeometry`, `CylinderGeometry`, `ExtrudeGeometry`, `ConeGeometry` 进行位移、旋转和缩放变换（`applyMatrix4`）。
2. **静态网格合并（Geometry Merging）**：
   - 静态实体（如码头基座、立柱、缆绳桩、栈桥地板、货箱、灯塔）必须合并为统一的单一 `BufferGeometry`，统一指派材质，杜绝分散的子 Mesh 拖垮性能。
3. **顶点着色与微细节注入**：
   - 在程序化生成几何体时，通过设置 `geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3))` 注入顶点颜色，使低多边形物体展现木纹深浅、磨损边缘与地表明暗。

## 3. 程序化船只与滑板生成标准
- **水上滑板 (Water Skateboard / Surfboard)**：
   - 流线型板面，前翘冲角（Rocker），底部导流鳍（Fins），板身带有防滑垫程序化纹理，尾部绑定动态水花发射点。
- **古代中式帆船 / 郑和宝船 (Zheng He Flagship / Warship)**：
   - 经典的福船/宝船造型：多道肋骨构成的流线木质船壳（Hull）、艏楼（Bow Deck）、多层艉楼（Stern Castle）、三至四面硬帆结构（Battern Sails）、主甲板缆绳与舵轮。
   - 所有部件由程序化参数控制，可灵活调节船长、宽、吃水线与帆面展开角度。
