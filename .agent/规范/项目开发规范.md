# 项目开发规范

## 1. 架构目标与技术选型

本项目为基于 WebGL / Three.js 开发的大型开放式航海 RPG 游戏，融合《新郑和下西洋》的航海探索特色与 Saltline 的全代码自洽生成架构。

- **核心渲染引擎**：Three.js (WebGL 2.0 / WebGLRenderer)
- **UI 与 HUD 框架**：轻量级自适应 Canvas 2D + HTML5/CSS3 游戏界面（包含准星/摇杆、小地图、载具状态面板）
- **开发与构建模式**：模块化 ES 模块系统，支持独立静态网页直接加载与本地 HTTP 服务（如 `python -m http.server` 或 Vite）零配置快速预览。

## 2. 目录结构与分层架构

项目代码按职责明确分层，避免跨层污染与高耦合：

```
xzh/
├── .agent/规范/                 # 规范文档中心
├── src/
│   ├── core/                    # 引擎核心：渲染循环、主场景、相机、输入管理器、事件总线
│   ├── world/                   # 世界系统：大地图地形高度场、岛屿、植被、码头与港口设施
│   ├── ocean/                   # 水体系统：GPU FFT 频谱海洋、浪花计算、浮力高度采样
│   ├── sky/                     # 天空系统：大气散射、太阳方位、动态光照与体积云
│   ├── entities/                # 实体与载具：角色(Player)、水上滑板(Board)、郑和宝船/战舰(Ship)
│   ├── ui/                      # 界面系统：HUD、M键小地图(Minimap)、载具切换提示、操作指南
│   └── audio/                   # 算法音频：基于 Web Audio API 的算法声效合成器
├── index.html                   # 游戏启动主入口
└── README.md                    # 项目说明
```

## 3. 代码风格与规范约定
1. **语言要求**：
   - 所有解释、交互文档、代码注释及 JSDoc 必须使用 **简体中文 (Simplified Chinese)**。
2. **命名规约**：
   - 类名采用大驼峰：`SpectralOcean`, `ShipController`, `MinimapUI`。
   - 变量与方法采用小驼峰：`currentVehicle`, `sampleWaterHeight(x, z)`。
   - 常量采用大写下划线：`WATER_BASE_LEVEL`, `DEFAULT_WIND_SPEED`。
3. **资源生命周期管理 (Dispose Protocol)**：
   - 严禁出现未受控的 Geometry / Material / WebGLRenderTarget 创建。
   - 任何实体或场景在销毁/重建时，必须严格执行递归 `dispose()`，释放 GPU 显存。
4. **性能基准与 Draw Call 预算**：
   - 目标帧率：PC 端稳定 60 FPS。
   - 静态场景元素（码头支柱、木板、围栏、岩石群）必须在初始化阶段通过 BufferGeometry 合并为单个网格，全场景静态网格 Draw Calls 控制在 30 次以内。


## 4. 工程反思与团队惯例 (Continuous Retrospection)
1. **ES Module 与本地离线依赖策略**：
   - 为避免外网 CDN 网络波动或断链，关键核心库（如 Three.js）统一存放在本地 `lib/three.module.js`，保证在无外网环境下 `python -m http.server` 能百分之百正常启动运行。
2. **CPU 与 GPU 双端波浪方程同步规约**：
   - 载具（战船、滑板）和角色的物理浮力采样必须与水面顶点着色器的 Gerstner / FFT 频谱参数严格同源同步，确保所见即所浮，杜绝视觉穿帮。
3. **载具三态切换与安全校验**：
   - 切换战船/滑板时，必须实时检测当前海拔地形。高陆地区域拦截召唤并给予友好 HUD 引导，避免巨型战船在陆地产生穿模。
4. **混合渲染管线与高保真资产集成**：
   - 当追求原生级画质（如《vue3-threejs》参考工程）时，严禁使用粗糙无材质的简陋几何体替代；必须采用 GPU 多频 FFT 水体、真实大气查找表（LUTs）与 2K PBR 模型相融合的高清管线。
5. **动态程序化 Canvas 纹理生成体系**：
   - 对于零外置贴图依赖的自研角色与载具（大明水手、神机滑板），通过 HTML Canvas 2D 动态生成精致的五官面容、大明水师官阶刺绣补子、竹篾编织斗笠与能量导轨流线贴图，结合 MeshStandardMaterial 达到高精度的国风航海视觉表现。
